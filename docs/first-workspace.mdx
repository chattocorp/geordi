# Your first workspace

Give an agent a small README edit, then review the change beside the conversation. A workspace gives the agent its own Git branch and working directory. You can keep using your original checkout while it works.

## Open Geordi

Start with a local Git repository that has a committed README. Sign in to Claude Code or Codex on the same machine. If you want to open a GitHub pull request at the end, use a clone you can push to and sign in with `gh auth login`.

[Download the desktop app](https://geordi.run/#install) and open Geordi. You can also follow this guide in your browser. With Node.js 24 or newer, run `npx geordi` and open the local address it prints. Keep the command running while you work.

## Add your repository

1. On **New workspace**, select **Add repository…**.
2. In the desktop app, choose the folder that contains your local checkout. In a browser, enter its path on the Geordi host, such as `~/src/my-project`, and select **Add repository**.
3. Check the repository name below the message box. Geordi selects the repository you just added.

## Give the agent a small change

Choose a model from the agent you signed in to. Check the permission mode before sending. **Full Access** lets the agent act with your user account’s permissions. **Auto Mode** uses the agent’s automatic permission controls.

In **What should the agent do?**, enter a task you can review in one file. For a practice repository, try this:

## Review the diff

When `README.md` appears under **Changes**, select it. A tab opens beside the conversation tab and shows the added line. Compare the sentence with your request. To revise it, return to the conversation and tell the agent what to change.

## Open a pull request

Look at the **ribbon** at the top of the workspace. After the README edit, it says **Uncommitted changes**. The button at the far right is the next step. On a supported forge, select **Create PR**. Geordi sends the agent a message to commit the edit, push the branch and open a pull request. If you're using a local-only repository, select **Commit** to save the edit on the workspace branch.

Once the pull request exists, select its number in the ribbon to see its description, reviews and checks inside Geordi. If you ask the agent for another edit, **Update PR** sends those changes to the same pull request.

## Read the sidebar pills

When you have several workspaces open, look at the right edge of each sidebar row. Hover over a row or use Tab to focus its action. The colored circle expands into a pill with the same action you would find in that workspace’s ribbon. Select the pill to act while you keep reading your current conversation.

| What you see                     | What you can do                                                                                     |
| -------------------------------- | --------------------------------------------------------------------------------------------------- |
| Red **Fix errors**               | Ask the agent to read the failing checks, fix the cause, commit and push.                           |
| Red **Resolve conflicts**        | Ask the agent to merge the latest base branch, resolve conflicts, run the relevant checks and push. |
| Red **Address review**           | Ask the agent to read the requested changes, address them and update the pull request.              |
| Green **Merge PR**               | Merge through the forge. Geordi handles the merge directly.                                         |
| Purple **Archive** after a merge | Put the finished workspace away. Its conversation is available in **Archive**.                      |

If the workspace has both conflicts and a failing check, the sidebar offers **Resolve conflicts** first. Open the workspace to see both actions in the ribbon.

A spinner means the agent is working. If the agent needs your input, the question icon takes you to the question. A checks indicator shows progress while CI runs. Routine publishing actions such as **Create PR** and **Update PR** stay in the ribbon and become available when the agent finishes its turn.

## Merge and finish

When the ribbon says **Ready to merge**, review the pull request and select **Merge PR** there or in the sidebar. If GitHub offers **Auto-merge** while requirements are pending, you can ask GitHub to merge once they pass. **Disable Auto-merge** withdraws that request.

After the merge, use **Archive** if the task is complete. If you want the same agent to do follow-up work, select **Continue** in the ribbon. Geordi keeps the conversation and starts a fresh branch from the latest upstream.
